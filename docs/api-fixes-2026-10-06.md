# API fixes: 6 Oct 2026

**Symptom:** every chat message returned `500 Internal Server Error`.

```bash
curl -i -X POST http://127.0.0.1:8000/api/sessions/<thread_id>/messages \
  -H "Content-Type: application/json" \
  -d '{"text": "Find economy flights from DEL to DXB for 2 passengers on 2026-10-10", "client_id": "test-001"}'
# HTTP/1.1 500 Internal Server Error
```

**Result:** 7 issues fixed in 4 files. The 500 is gone, and the message → search → approval → reply flow works end to end.

| # | Severity | File | Issue |
|---|---|---|---|
| 1 | 🔴 crash | `app/api/routes.py` | Called a method that does not exist → 500 |
| 2 | 🔴 stuck | `app/api/routes.py` | A crash left the session locked forever → 409 on every later message |
| 3 | 🟠 hidden | `app/api/routes.py` | `except Exception: pass` swallowed every failure |
| 4 | 🟠 contract | `app/api/routes.py` | Approval body did not match what the UI sends |
| 5 | 🔴 silent | `app/agent/tools.py`, `app/agent/approval.py` | `thread_id` was always `None` → tool events never published |
| 6 | 🔴 data loss | `app/api/runner.py` | Each new turn wiped the held booking from agent state |
| 7 | 🟠 duplicate | `app/agent/approval.py` → `app/api/runner.py` | `approval.required` sent twice after resume |

---

## 1. The 500: `TurnManager.run` does not exist

**Where:** `app/api/routes.py`, `send_message`

```python
# before
asyncio.create_task(
    turn_manager.run(          # ← TurnManager has no run() method
        thread_id,
        execute,
    )
)
```

`TurnManager` (`app/api/turns.py`) only has `is_busy`, `acquire`, `release`, `set_waiting_for_approval` and `is_waiting_for_approval`.
The request handler raised `AttributeError: 'TurnManager' object has no attribute 'run'` and FastAPI answered with a plain-text 500.

**Fix:** `execute` is already an `async def`. Calling it gives a coroutine, which is what `create_task` needs:

```python
# after
start_background(execute())
```

## 2. The session stayed locked after the crash

**Where:** same handler. `turn_manager.acquire(thread_id)` runs **before** the line that crashed. Nothing released the lock, so every later message to that session got `409 turn_in_progress` until uvicorn restarted.

**Fix:** if starting the task fails, release the lock right there.

```python
try:
    start_background(execute())
except Exception:
    # Nothing started, so nothing will ever release the lock: do it here.
    turn_manager.release(thread_id)
    raise
```

`start_background` also keeps a reference to the task. **asyncio holds tasks only weakly**, so a task nobody references can be garbage-collected halfway through a turn.

```python
_background_tasks: set[asyncio.Task] = set()

def start_background(coro) -> None:
    task = asyncio.create_task(coro)
    _background_tasks.add(task)
    task.add_done_callback(_background_tasks.discard)
```

## 3. Errors were swallowed

**Where:** both `execute()` functions in `routes.py`.

```python
# before
except Exception:
    pass
```

A failing turn left no trace on the server. **Fix:** log with the full traceback. `run_turn` still publishes the `error` event for the UI.

```python
# after
except Exception:
    logger.exception("turn failed (thread %s)", thread_id)
```

## 4. Approval body did not match the UI

**Where:** `ApprovalRequest` in `routes.py`.

```python
# before                       # after (contract §3.4)
class ApprovalRequest:         class ApprovalRequest(BaseModel):
    approved: bool                 decision: Literal["approved", "rejected"]
```

The UI sends `{"decision": "approved" | "rejected"}`, so the old model would have answered every click with `422`.
The handler now resumes with `approval=request.decision == "approved"`.

## 5. `thread_id` never reached the graph nodes

This was the most important bug, because it failed **without any error**.

**Where:** `app/api/runner.py` put `"_thread_id": thread_id` into the graph input. `tools.py` and `approval.py` read it with `state.get("_thread_id")`.

**Why it failed:** LangGraph keeps only the keys declared in the state schema (`AgentState`) and **silently drops everything else**. Proof:

```python
class S(TypedDict):
    a: int

await graph.ainvoke({"a": 1, "_thread_id": "T1"}, config={"configurable": {"thread_id": "T1"}})
# node sees keys: ['a']        <- _thread_id is gone
# config["configurable"]["thread_id"] == "T1"
```

**Effect:** `thread_id` was always `None`:
- `flights.results`, `booking.updated` and `payment.updated` were **never published**, because `if thread_id:` was always false;
- `approval.resolved` was published to a thread called `None`.

**Fix:** `thread_id` is not state; it is run configuration. Nodes receive it through LangGraph's second parameter:

```python
from langchain_core.runnables import RunnableConfig

async def execute_tools(state: AgentState, config: RunnableConfig):
    thread_id = config["configurable"]["thread_id"]

async def approval_node(state: AgentState, config: RunnableConfig):
    thread_id = config["configurable"]["thread_id"]
```

`_thread_id` was removed from the runner's input.

## 6. Every turn wiped the booking

**Where:** `run_turn` in `runner.py`.

```python
# before: sent on EVERY turn
{
    "messages": [...],
    "user_id": user_id,
    "booking": None,          # ← overwrites the checkpointed booking
    "payment": None,
    "db_booking_id": None,
    "_thread_id": thread_id,
}
```

The input of `ainvoke` is **merged into the saved checkpoint**. After a flight was held, the next message ("pay for it") would set `booking`, `payment` and `db_booking_id` back to `None`, and the agent would forget the booking.

**Fix:** send only what is new this turn.

```python
# after
{
    "messages": [{"role": "user", "content": message}],
    "user_id": user_id,
}
```

`messages` still appends correctly because of its `operator.add` reducer. The other keys keep their checkpointed values. The first turn is fine without them too, since nodes read them with `state.get(...)`.

## 7. `approval.required` was published twice

**Where:** `approval.py` published the event just **before** `interrupt()`.

**Why that duplicates:** on resume, LangGraph **re-runs the paused node from the top**, and only then does `interrupt()` return the user's answer. Everything before `interrupt()` runs twice: the event was published again, and the flight was re-fetched from Duffel.

**Fix:** the node only calls `interrupt(approval_data)`. The runner publishes the event once, when the graph pauses:

```python
# runner.py, run_turn
interrupts = result.get("__interrupt__")
if interrupts:
    await event_bus.publish(
        thread_id,
        SSEEvent(event="approval.required", data=interrupts[0].value),
    )
```

|---|---|
| `POST /messages` | **202** `{"accepted":true}` (was 500) |
| second `POST /messages` while the turn runs | **409** `turn_in_progress` |

| `POST /approvals/x {"decision":"rejected"}` | **202** → `approval.resolved` → assistant reply |
| booking created on rejection | ❌ none (correct) |

```
#3 approval.required  Duffel Airways DEL → DXB …

   POST /approvals {"decision":"rejected"}

#7 step.updated       approval / completed
#8 step.updated       thinking / completed

```

### Environment notes
- The first test run failed with `Connect call failed ('127.0.0.1', 5432)`. That was not a code bug: Docker Desktop and the `flight_booking_postgres` container were stopped. Start them before running the API:
  ```bash
  open -a Docker
  docker start flight_booking_postgres
  ```
- **Restart uvicorn after pulling these fixes.** `TurnManager` lives in memory, and any session locked by the old bug stays locked until the process restarts.

## Lessons (interview-worthy)

1. **LangGraph state is schema-filtered.** Undeclared input keys vanish without an error. Per-run values (thread id, user, request id) belong in `config`, not in state.
2. **`ainvoke` input is merged into the checkpoint.** Re-sending defaults on every turn erases memory.
3. **`interrupt()` re-executes the node on resume.** Side effects before it run twice. Keep them out of the node, or make them idempotent.
4. **Background tasks need a strong reference.** `asyncio.create_task` alone can lose a task to garbage collection.
5. **Lock, then release on every exit path**, including "the task never started".
6. **Never `except: pass` in a background task.** Nobody is waiting for its result, so a swallowed error is invisible.
